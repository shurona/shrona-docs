# 핵심 철학
- 에이전트가 규칙을 어겼을 때 프롬프트를 고치는 것이 아니다.
- 그 실패가 구조적으로 불가능 하도록 마구를 고치는 것이다. 
# 4개의 기둥
## 기계가 읽는 컨텍스트
- 단순한 문서가 아니라 AI가 실행하는 런타임 설정 파일
- AGENTS.md 파일을 작성해서 AI에게 줄 지침서를 설계
## 결정론적 CI/CD 게이트
- 문서만 해놓으면 AI가 실수를 할 수 있기 때문에 구조적으로 막는 것이다.
- 린터나 구조 테스트
	- 자동 교정 루프
## 명시적 도구 경계
- AI가 어디까지 접근할 수 있는 지 제한할 수 있다. 
- 도구적인 경계는 물리적인 차단
## 지속적 피드백 루프
- 기존 코드를 참고해서 새 코드를 작성하는데 이 때 기존 코드가 좋지 않은 패턴을 갖고 있으면 문제가 늘어남으로 이를 방지하기 위함이다.
- 에이전트가 실수할 때 마다 새로운 린터가 생성될 수 있다. 
	- 규칙이 지속적으로 보강이 된다.
# 시스템 4단계 작동
## 분류기
- 작업 유형 판별
## 컨텍스트 관리자
- 필요한 파일과 규칙만 골라서 제공
## 실행 루프
- 테스트 통과할 때 까지 자동 반복
## 워커 격리
- 코드 작성 Ai와 코드 검토 AI는 분리해야 한다.
