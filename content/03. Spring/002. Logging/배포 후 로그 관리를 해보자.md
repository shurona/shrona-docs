# 배포 후 로그 관리를 해보자

## 왜 시작했는가

현재 운영 서버는 Docker로 배포하고 있고, 로그 확인은 `docker logs` 명령어로만 하고 있다.
애플리케이션은 별도의 로깅 설정 없이 Spring Boot 기본값(Logback, 루트 레벨 INFO, 콘솔 출력)을 그대로 사용 중이다.

이 방식의 문제는 다음과 같다.

1. **컨테이너가 삭제되면 로그도 사라진다** - 재배포하면 이전 로그를 볼 수 없다. 장애 조사 중 "배포 전 로그"가 필요한 순간 방법이 없다.
2. **로테이션이 없어서 디스크가 찬다** - Docker의 json-file 로그 드라이버는 기본 설정으로는 무제한으로 쌓인다.
3. **검색과 집계가 안 된다** - 인스턴스가 여러 개면(admin/webapp 분리 배포) 한 요청의 흐름을 보려고 컨테이너별 `docker logs`를 눈으로 뒤져야 한다.
4. **로그 레벨 제어가 안 된다** - 설정이 없으니 전부 INFO 고정이고, 운영 중에 특정 패키지만 DEBUG로 올릴 수도 없다.

## 학습 로드맵

### 1단계. SLF4J와 Logback의 관계 이해
- SLF4J는 API(인터페이스), Logback은 구현체이다. `@Slf4j`가 만들어주는 것은 SLF4J의 Logger이고, `spring-boot-starter-logging`이 Logback을 기본 구현체로 연결해 준다.
- 핵심 개념: Logger(이름 계층 구조) / Appender(어디로 쓸지) / Encoder·Pattern(어떤 형식으로) / Level(TRACE ~ ERROR)

### 2단계. yaml `logging:` 설정만으로 되는 것
- `logback-spring.xml` 없이도 `logging.level`, `logging.file.name`, `logging.pattern` 정도는 yaml로 가능하다.
- 프로필별로 local은 DEBUG, prod는 INFO처럼 분리하는 것부터 시작한다.

### 3단계. logback-spring.xml 작성
- appender를 여러 개 쓰거나 로테이션을 세부 제어하려면 이 파일이 필요하다.
- `RollingFileAppender` + `SizeAndTimeBasedRollingPolicy` (일별 롤링 + 파일당 크기 제한 + 보관 기간)
- `<springProfile>` 태그로 프로필별 분기

### 4단계. Docker 환경에서의 선택지 (중요한 갈림길)
- 12-factor 원칙: 앱은 stdout에만 쓰고, 수집은 인프라가 담당한다.
- **A안. stdout 유지 + 인프라 보강**: docker-compose에 `max-size`, `max-file` 로테이션 설정 + 로그 수집기 연결. 최종적으로 표준이 되는 방향.
- **B안. 파일 appender + 볼륨 마운트**: 컨테이너 밖 호스트 디렉토리에 로그 파일을 남긴다. 수집기 없이 "재배포해도 로그 보존"이 당장 필요하면 가장 빠른 해법.

### 5단계. 구조화(JSON) 로깅과 MDC
- 검색 가능한 로그의 전제 조건이다.
- Spring Boot 3.4부터는 별도 라이브러리 없이 네이티브 구조화 로깅을 지원한다: `logging.structured.format.console: ecs`
- MDC로 요청별 correlation ID를 모든 로그 라인에 자동으로 붙인다.

### 6단계. 중앙 수집 - Loki + Grafana
- 이미 Prometheus + Actuator를 쓰고 있다면 같은 Grafana 생태계인 Loki(저장) + Promtail/Alloy(수집)가 자연스럽다.
- ELK는 소규모 운영에는 부담이 크다. → 이전에 정리한 [[ELK 적용 과정]] 참고
- 메트릭과 로그를 Grafana 한 화면에서 보게 된다.

### 7단계. 운영 편의
- Actuator `loggers` 엔드포인트를 열면 재배포 없이 런타임에 로그 레벨을 바꿀 수 있다.

## 적용 순서 요약

| 순서 | 작업 | 효과 |
|------|------|------|
| 1 | docker-compose 로그 로테이션 옵션 | 디스크 참사 방지 (5분 작업) |
| 2 | yaml `logging.level` 프로필별 설정 | 레벨 제어 시작 |
| 3 | logback-spring.xml 파일 롤링 + 볼륨 마운트 | 재배포해도 로그 보존 |
| 4 | 구조화 로깅 + MDC | 검색 가능한 로그 |
| 5 | Loki + Grafana | 중앙 수집, 최종 형태 |

1~3단계만 해도 "재배포하면 로그가 사라지는" 문제는 해결된다.
