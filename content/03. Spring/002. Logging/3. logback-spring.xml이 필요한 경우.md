# 3. logback-spring.xml이 필요한 경우

> [[배포 후 로그 관리를 해보자]] 로드맵의 3단계

## 지금은 만들지 않는다

mommytalk에는 아직 `logback-spring.xml`이 필요하지 않다. 2단계에서 로그 레벨, 콘솔과 파일 패턴, 파일 출력, 날짜와 크기 기준 롤링, 보관 기간과 전체 용량 제한을 모두 YAML로 설정했다.

같은 설정을 XML로 다시 작성하면 설정 위치만 두 곳으로 나뉜다. YAML로 할 수 없는 요구가 생기기 전까지는 지금 구성을 유지한다.

## charity 설정과 비교

참고한 파일은 charity의 `charity-server/src/main/resources/logback-spring.xml`이다.

XML의 local 프로필 블록은 Spring Boot의 `base.xml`을 불러오고 `org.springframework.jdbc`를 DEBUG로 설정한다. 별도로 공통 `application.yml`에서 `kr.or.missionaid`를 DEBUG로 두기 때문에 실제 애플리케이션 패키지는 모든 프로필에서 DEBUG이다. 운영에 해당하는 default 프로필은 CONSOLE과 FILE appender를 직접 만들고, `/application/logs/spring/app.log`를 날짜마다 압축한다. 보관 기간은 30일이다.

charity가 XML에서 하는 일은 mommytalk의 현재 YAML 설정과 다음처럼 대응한다.

| charity의 XML 설정 | mommytalk의 YAML 설정 |
|---|---|
| `<logger>`, `<root>` | `logging.level` |
| `<file>` | `logging.file.name` |
| `<encoder><pattern>` | `logging.pattern.console`, `logging.pattern.file` |
| `<fileNamePattern>`, `<maxHistory>` | `logging.logback.rollingpolicy` |
| `<springProfile>` | `application-local.yaml`, `application-prod-*.yaml` |

mommytalk에서 지금 필요한 파일 로그는 YAML만으로 충분하다. 다만 charity는 파일 크기와 관계없이 날짜만으로 나누는 순수 `TimeBasedRollingPolicy`를 사용한다. Spring Boot 기본 파일 출력은 날짜와 크기를 함께 보는 정책이므로 charity의 동작을 세부적으로 똑같이 재현해야 한다면 XML이 필요하다.

## 사용되지 않는 JSON 설정

charity의 `resources/logback/json.xml`에는 별도의 JSON 파일 appender가 있다. `LogstashEncoder`를 사용하고 시간과 크기를 함께 기준으로 롤링한다. 관련 라이브러리도 `build.gradle`에 들어 있다.

하지만 `logback-spring.xml`에서 이 파일을 include하지 않고 `json` appender를 참조하지도 않는다. 현재 실행되는 설정이 아니라 JSON 로그 연동을 준비했던 흔적으로 보는 것이 맞다.

이 파일의 주석도 그대로 믿으면 안 된다.

- `maxHistory 10`은 총 용량이 아니라 보관할 시간 구간의 수이다. 파일 이름에 시간(`yyyy-MM-dd-HH`)이 들어가므로 이 설정에서는 10시간 구간을 뜻한다.
- `totalSizeCap 1GB`는 파일 개수가 아니라 압축 파일 전체 용량의 상한이다.

## XML이 필요한 시점

다음과 같은 요구가 생기면 `logback-spring.xml`을 작성한다.

- 목적이 다른 파일 appender를 여러 개 둘 때
- appender마다 필터나 로그 레벨을 다르게 적용할 때
- 특정 패키지나 Marker의 로그를 별도 파일로 보낼 때
- 비동기 appender나 Spring Boot 기본 설정으로 표현하기 어려운 encoder를 사용할 때

현재 mommytalk에는 이 요구가 없다. 다음 단계에서는 XML을 추가하지 않고, Docker에서 stdout을 유지할지 파일을 볼륨으로 보존할지 결정한다.
